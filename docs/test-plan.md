# MVP 테스트 계획

구현 후 테스트 코드는 `backend/tests/unit`, `backend/tests/integration`, `backend/tests/contract`에 둔다. 외부 API는 고정 fixture 또는 모의 어댑터로 대체하여 재현성을 보장한다.

| 구분 | 위치 | 확인 대상 |
| --- | --- | --- |
| 단위 | `backend/tests/unit` | 금액·기간·성향 검증, 1차 필터, 지표, MDD, 정규화, 점수, 주요 종목 편입 현황, 뉴스 정제 |
| 통합 | `backend/tests/integration` | 수집→필터→정량→최근 1주일 뉴스 수집·1개월 확장→AI→결과 조립의 부분 실패 격리 |
| 계약 | `backend/tests/contract` | `POST /api/analyses`의 요청 검증과 완료·부분·실패 응답 |
| 고정 데이터 | `backend/tests/fixtures` | ETF 메타데이터, 가격, 거래량, 뉴스·DART 표본 |

현재 구현 범위의 추가 검증: KRX 설정 누락 시 안전한 부분 결과, SQLite 캐시가 비어 있을 때 KRX 수집·저장, 당일 캐시가 있을 때 DB 재사용, 레버리지·인버스 제외, 위험 성향별 ETF 유형, 최소 1주 매수 가능 여부, 선호 자산 우선 정렬, 201개 이상 후보에서 상위 200개 제한을 단위 테스트로 확인한다.

필수 시나리오: 정상 입력, 투자금·기간 경계, 29/30개 주간 관측값, 0 이하 가격·중복 날짜·결측값, 변동성 0, 주요 종목 편입률·총 ETF 자산 비중의 계산·누락 사유, 201개 1차 후보·31개 뉴스 후보, 최근 1주일 정제 뉴스가 100건 미만일 때 최근 1개월까지 확장, 뉴스 없음, AI 시간 초과·형식 오류, 근거와 다른 AI 수치 제거, 180초 초과 시 부분 결과 또는 실패, `allocation_pending` 상태이다.

# MVP 계획서

## 1. MVP 목표

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | AI 에이전트를 활용한 금융 데이터 분석 및 추천 시스템 |
| 기준 문서 | `docs/requirements.md`, `docs/function-breakdown.md` |
| 적용 템플릿 | `C:\Users\Miche\.codex\templates\mvp-plan-template.md` |
| MVP 한 줄 설명 | 사용자가 투자 조건을 입력하면 국내 ETF 데이터를 규칙 기반으로 분석하고, 최근 뉴스에 근거한 설명을 결합하여 ETF 구성 후보 예시·선정 근거·위험요인을 한 화면에 제공하는 서비스 |
| 검증할 핵심 가치 | 비전문 투자자가 여러 ETF의 정량지표, 뉴스 근거와 데이터 한계를 함께 비교하여 자신의 투자 판단에 참고할 수 있는가를 검증한다. |
| 시연 방식 | 회원가입 없이 한 명의 사용자가 한 화면에서 조건을 입력하고 동기식 분석 결과를 확인한다. |

MVP 결과는 정보 제공과 투자 판단 보조를 위한 투자 예시이며, 특정 ETF의 매수·매도 지시나 투자 성과 보장을 의미하지 않는다. ETF별 포트폴리오 배분 산식은 아직 확정되지 않았으므로 실제 ETF 비중과 배분 금액은 생성하지 않는다.

### 계산·규칙과 AI 에이전트의 책임 분리

| 구분 | 담당 범위 | 금지 사항 |
| --- | --- | --- |
| 일반 코드 | 입력 검증, ETF 수집·필터링, 수익률·변동성·MDD·샤프지수·유동성·비용·편입 현황·기대수익률 계산, 최소–최대 정규화, 위험 성향별 가중 점수, 후보 순위, 데이터 품질·상태 검증 | 원천 데이터에 없는 값을 추정해 채우거나 AI 출력값으로 계산 결과를 변경하지 않는다. |
| AI 에이전트 | 정제된 뉴스·공시의 요약과 감성 분석, 사용자 조건·정량 결과·뉴스·데이터 한계를 구분한 선정 근거와 위험요인 설명 생성 | 정량값 재계산·수정, 후보 점수·순위·ETF 비중 생성, 원천에 없는 사실·전망 추가를 금지한다. |

## 2. MVP 사용자 흐름

| 순서 | 사용자 또는 시스템 | 동작 | 사용자가 확인하는 결과 |
| --- | --- | --- | --- |
| 1 | 사용자 | 투자금, 투자 기간, 위험 성향, 허용 손실을 입력하고 선호 자산·현금성 비중을 선택한다. | 입력값, 필수·선택 구분과 필드별 오류 안내 |
| 2 | 화면·Backend | 입력값의 필수 여부, 형식과 허용 범위를 검증한다. | 오류가 있으면 분석이 시작되지 않고 수정할 필드와 허용 범위가 표시됨 |
| 3 | Backend | `POST /api/analyses` 한 요청으로 동기식 분석을 시작한다. | 분석 중 상태와 중복 요청 차단 상태 |
| 4 | 일반 코드 | 국내 ETF 기본정보를 확인·갱신하고 기본 품질과 사용자 조건으로 1차 후보를 최대 200개 선정한다. | 후보 수, 적용 규칙과 제외 사유 |
| 5 | 일반 코드 | 후보별 가격·거래·비용·상품·구성 종목 데이터를 수집·검증하고 정량지표와 기대수익률 추정치를 계산한다. | 지표값 또는 지표별 산출 불가 사유, 기간·기준일·단위·출처 |
| 6 | 일반 코드 | 최소–최대 정규화와 위험 성향별 가중치를 적용하고 허용 손실 조건을 반영해 뉴스 분석 후보를 최대 30개 선정한다. | 후보별 정규화 값·점수·순위와 제외 사유 |
| 7 | 일반 코드 | 뉴스 API와 DART에서 관련 데이터를 수집하고 기간·중복·출처·관련성을 검증해 전체 최대 100건을 정제한다. | 사용·제외 뉴스 수, 검색 기간, 출처와 제외 사유 |
| 8 | AI 에이전트 | 검증된 뉴스·공시를 ETF별로 요약하고 감성을 분석한다. | 출처 참조가 있는 요약·감성 또는 뉴스 없음·AI 실패 상태 |
| 9 | 일반 코드·AI 에이전트 | 코드 결과를 보존하면서 사용자 조건·정량 결과·뉴스 결과·데이터 한계를 결합해 선정 근거와 위험요인을 생성·검증한다. | 근거 유형과 출처가 연결된 설명, 부분 결과와 분석 한계 |
| 10 | 화면 | ETF 구성 후보 예시, 확정 제약조건, 사용자 선택 현금성 비중, ETF별 지표·기대수익률 추정치·뉴스 설명·위험요인과 책임 제한 안내를 한 페이지에 표시한다. | 결과가 투자 참고 정보이며 실제 ETF 배분 산식은 보류 상태임을 확인 |

정상 처리 시 Backend는 최대 3분(180초) 안에 완료 결과를 반환한다. 3분(180초) 안에 전체 분석을 완료하지 못했지만 검증된 결과가 있으면 시간 초과 사유를 포함한 부분 결과를 반환하고, 검증된 결과가 없으면 실패 결과를 반환한다.

## 3. MVP 포함 기능

| 번호 | 기능 | 설명 | 포함 이유 | 담당 |
| --- | --- | --- | --- | --- |
| 1 | 투자 조건 입력 화면 | 투자금 100만~10억 원, 투자 기간 1개월~5년, 안정형·중립형·공격형, 허용 손실, 선호 자산과 현금성 비중을 입력한다. | 분석의 시작점이며 사용자 조건 검증에 필요하다. | 화면·일반 코드 |
| 2 | 입력 검증과 안내 | 필수값·자료형·범위·선택값을 검증하고 필드별 수정 메시지를 제공한다. | 잘못된 입력으로 분석이 실행되는 것을 방지한다. | 화면·일반 코드 |
| 3 | 동기식 분석 API | Frontend는 `POST /api/analyses` 하나만 호출하고 Backend는 최대 3분(180초) 안에 완료·부분 결과·실패 중 하나를 반환한다. | 입력부터 결과 확인까지 단일 사용자 흐름을 연결한다. | 일반 코드 |
| 4 | ETF 기본정보 수집·갱신 | 국내 상장 ETF 목록을 KRX 기준으로 관리하고, DART·KSD·운용사 공식 자료로 필요한 정보를 보완한다. | 분석 가능한 ETF 모집단과 데이터 계보를 확보한다. | 일반 코드 |
| 5 | 1차 규칙 기반 필터링 | 기본 품질과 사용자 조건을 적용해 후보를 최대 200개로 제한하고 포함·제외 근거를 기록한다. | 상세 데이터 수집 범위와 처리량을 제한한다. | 일반 코드 |
| 6 | 후보 상세 데이터 수집 | 조정 종가, 거래량·거래대금, 비용, 상품 분류, 순자산, 구성 종목과 편입 비중을 수집·검증한다. | 정량분석과 결과 설명의 원천 데이터가 된다. | 일반 코드 |
| 7 | 정량지표 계산 | 기간 누적 수익률, 주간 단순·로그 변동성, MDD, 샤프지수, 평균 거래량, 비용과 ETF 편입 현황을 계산한다. 기대수익률은 월말 조정 종가의 ETF 기하연환산 값 40%와 동일 자산군 중앙값 60%를 결합하고 투자 기간 누적값으로 환산한다. 추세 조정·블록 재표본추출 범위·과거 검증 오차는 각 정책이 확정된 경우에만 계산한다. | ETF의 수익·위험·유동성을 비교하고 기대수익률 추정치의 기준과 한계를 제공하는 핵심 기능이다. | 일반 코드 |
| 8 | 데이터 품질과 산출 불가 처리 | 결측·0 이하 가격·IQR 이상값·중복 날짜·최소 관측값·0으로 나누기 상황을 검증하고 지표별 오류를 격리한다. | 일부 오류가 전체 결과를 무효화하지 않도록 한다. | 일반 코드 |
| 9 | 정규화·점수화 | 최소–최대 정규화와 위험 성향별 가중치를 적용하고 평균 거래량을 유동성 점수로 사용한다. | 사용자 성향에 맞는 후보 순위를 재현 가능하게 생성한다. | 일반 코드 |
| 10 | 뉴스 분석 후보 선정 | 허용 손실 조건을 적용한 뒤 정량 점수 순으로 최대 30개 ETF를 선정한다. | 뉴스·AI 처리량을 제한한다. | 일반 코드 |
| 11 | 뉴스·공시 수집과 정제 | 뉴스 API와 DART에서 최근 1주일 영업일 기준으로 수집하고 부족하면 1개월까지 확장한다. 중복·기간 밖·출처 누락·관련성 부족 데이터를 제외해 전체 최대 100건을 사용한다. | AI가 검증 가능한 원천만 해석하도록 한다. | 일반 코드 |
| 12 | 뉴스 요약·감성 분석 | ETF별 뉴스와 DART 공시를 요약하고 감성 결과와 근거 참조를 분리해 생성한다. | 정량지표만으로 확인하기 어려운 최근 이슈를 참고 정보로 제공한다. | AI 에이전트 |
| 13 | 종합 설명 생성·검증 | 사용자 조건, 정량지표, 뉴스 분석과 데이터 한계를 구분하여 선정 근거와 위험요인을 별도 필드로 생성하고 원천 근거를 검증한다. | 사용자가 결과의 이유와 한계를 확인하게 한다. | AI 에이전트·일반 코드 |
| 14 | ETF 구성 후보 예시 | 유효 후보가 30개 이상이면 구성 후보와 ETF 3~8개, 개별 5~30%, 동일 테마 40%, 단일 운용사 50% 등의 제약조건 및 사용자 선택 현금성 비중을 표시한다. 실제 ETF별 비중은 생성하지 않는다. | 배분 산식 확정 전에도 비교 가능한 투자 예시를 제공한다. | 일반 코드 |
| 15 | 한 페이지 결과 화면 | 사용자 조건, ETF별 정량지표·기대수익률 추정치, 뉴스 요약·감성, 선정 근거·위험요인, 출처·기준일·한계·책임 제한을 표와 차트로 표시한다. | 사용자가 입력부터 결과까지 한 흐름에서 확인할 수 있어야 한다. | 화면 |
| 16 | 완료·부분 결과·실패 처리 | 외부 데이터 없음, 일부 후보 실패, 뉴스 없음, AI 실패와 시간 초과에도 검증된 정량 결과를 보존한다. | 외부 의존 기능의 장애가 전체 분석을 불필요하게 중단하지 않도록 한다. | 일반 코드 |

## 4. MVP 제외 기능

| 번호 | 기능 | 제외 이유 | 후순위 처리 방향 |
| --- | --- | --- | --- |
| 1 | 회원가입·로그인·사용자 계정 | 단일 사용자 일회성 흐름 검증에 필요하지 않다. | 개인화와 권한 관리가 필요할 때 검토한다. |
| 2 | 사용자별 분석 이력 저장 | 로그인 없는 MVP 범위와 맞지 않고 사용자가 명시적으로 제외했다. | 계정 기능과 함께 검토한다. |
| 3 | 실시간 스트리밍·상태 폴링 | 동기식 단일 요청 방식으로 확정되었다. | 장시간 분석이 필요해질 때 비동기 처리와 함께 검토한다. |
| 4 | 실시간 주문·자동매매 | 정보 제공 목적을 넘어 실제 거래를 실행하므로 제외한다. | MVP 이후에도 별도 법적·보안 검토 없이는 포함하지 않는다. |
| 5 | 증권 계좌 연동 | 투자 예시 확인에 필수적이지 않고 민감한 금융정보 처리가 필요하다. | 별도 보안·권한 요구사항을 정의한 뒤 검토한다. |
| 6 | 결제·관리자 기능 | 핵심 분석 흐름과 직접 관련이 없다. | 운영 단계에서 필요성을 재평가한다. |
| 7 | ETF별 포트폴리오 배분 비중·금액 | 배분 산식·반올림·잔여금 처리 기준이 확정되지 않았다. | 정책 확정 후 결정적 계산 기능으로 추가한다. |
| 8 | 포트폴리오 기대수익률·샤프지수·비중 차트 | ETF별 배분 비중이 없으면 계산·표시할 수 없다. | 배분 산식 확정 후 추가한다. |
| 9 | 수익 보장·확정적 투자 추천 | 프로젝트 목적과 금융 정보 제공 원칙에 위배된다. | 추가하지 않는다. |
| 10 | 고급 UI·알림·보고서 다운로드 | 한 페이지 결과 확인만으로 핵심 가치 검증이 가능하다. | 핵심 흐름 안정화 이후 검토한다. |

ETF 목록과 최신 기준 데이터의 운영상 캐시·갱신은 분석 기능에 포함하지만, 사용자 입력·요청별 중간 결과·최종 분석 결과는 요청 종료 후 영구 보존하지 않으며 과거 분석 결과를 조회하는 이력 기능도 포함하지 않는다.

## 8. 가정 사항

| 번호 | 가정 사항 |
| --- | --- |
| 1 | MVP 분석 대상은 국내 상장 ETF이며 투자금 통화는 원화(KRW)이다. |
| 2 | 한 명의 사용자가 로그인 없이 한 번의 조건 입력과 결과 확인 흐름을 이용한다. |
| 3 | KRX·운용사 공식 자료·DART·뉴스 API·AI 서비스를 MVP에 포함하며, 실제 이용 가능 여부는 각 서비스의 신청·권한·호출 한도에 따른다. |
| 4 | ETF 목록·가격·거래 데이터는 KRX를 기준으로 하고 출처 충돌 시 승인된 출처 우선순위를 적용한다. |
| 5 | ETF 기준 데이터는 갱신 정책에 따라 운영상 캐시로 보존한다. 사용자 입력·요청별 중간 결과·최종 분석 결과는 응답 구성 중에만 임시로 사용하고 요청 종료 후 영구 보존하지 않는다. |
| 6 | 모든 정량 계산은 일반 코드의 결정적 규칙으로 수행하고 AI 에이전트는 설명 생성과 뉴스 해석에만 참여한다. |
| 7 | 뉴스 감성은 정량 점수·후보 순위·기대수익률·ETF 비중에 반영하지 않는다. |
| 8 | 기대수익률은 과거 데이터와 고정 가정에 따른 추정치이며 실제 성과를 보장하지 않는다. |
| 9 | ETF별 배분 산식이 확정되기 전까지 포트폴리오 결과는 구성 후보·제약조건·현금성 비중·보류 상태까지만 제공한다. |
| 10 | 처리 중 화면의 `분석 중`은 동기식 API 응답을 기다리는 임시 화면 상태이며 별도의 스트리밍이나 상태 조회 결과가 아니다. |

확인 필요 사항 중 구현 결과를 바꾸는 항목은 해당 구현 단계 전에 확정한다. 확정 전에는 임의의 기본값으로 대체하지 않는다.
